# НК-строй — демонстрационный контроль файлов

Mobile-first Web App на Google Apps Script для демонстрации пути прораба: выбор себя и закреплённого объекта, просмотр пяти обязательных позиций, прикрепление недостающих материалов, подтверждение и последовательная загрузка в Google Drive с обновлением Google Sheets.

## Важные ограничения и безопасность

- Это MVP только для тестовых данных. Не загружайте реальные персональные данные, документы клиентов и производственные материалы.
- Выбор прораба **не является авторизацией и не подтверждает личность**: любой пользователь со ссылкой может выбрать любого тестового прораба.
- Для рабочего решения потребуется идентификация по Google-аккаунту, Telegram ID либо персональной ссылке с токеном. Эти механизмы намеренно не реализованы в демо.
- Лимит — 10 МБ на каждый файл и 25 МБ суммарно на одну попытку отправки обязательной позиции. Base64 увеличивает объём передачи примерно на треть, а Apps Script имеет квоты и ограничения времени выполнения; прототип не предназначен для полноразмерных видео или высокой параллельной нагрузки.
- Одна обязательная позиция может содержать любое число небольших файлов. Их количество не контролируется.

## Структура проекта

| Файл | Назначение |
|---|---|
| `Config.gs` | Названия листов, заголовки, статусы, часовой пояс и лимит файла |
| `Code.gs` | Web App, HTML include и единый формат ответов |
| `SetupService.gs` | Создание и сброс демо-ресурсов и тестовых строк |
| `DataService.gs` | Чтение Sheets, карта заголовков, выборки и серверные проверки связей |
| `DriveService.gs` | Безопасные имена и повторное использование папок Drive |
| `UploadService.gs` | Проверка, декодирование, атомарная загрузка позиции и обновление Sheets |
| `Index.html` | Семантическая разметка экранов |
| `Styles.html` | Mobile-first оформление без внешних библиотек |
| `Scripts.html` | Клиентское состояние, FileReader и `google.script.run` |
| `appsscript.json` | V8 и часовой пояс `Europe/Moscow` |

## Таблица и заголовки

Заголовки всех листов находятся в строке 2. Сервер читает их по названию, а не по фиксированному номеру столбца, и сообщает об отсутствующем столбце.

- **Справочник прорабов:** ID прораба; ФИО прораба; Статус.
- **Объекты:** ID объекта; Название; Адрес; Номер договора; ID ответственного прораба; Ответственный прораб; Статус объекта.
- **Справочник файлов:** ID типа файла; Этап работ; Наименование обязательного файла; Категория файла; Порядок отображения; Статус позиции.
- **Файлы объектов:** ID обязательного файла; ID объекта; Название объекта; ID типа файла; Этап работ; Наименование обязательного файла; Категория файла; ID ответственного прораба; Ответственный прораб; Статус; Дата предоставления; Кто загрузил; Ссылка на материалы; Дата обновления.

## Установка в Google Apps Script

1. Создайте отдельный standalone-проект на [script.google.com](https://script.google.com/) либо клонируйте файлы через `clasp` (сам `clasp` проекту для работы не требуется).
2. Создайте файлы с теми же именами и перенесите содержимое репозитория. Manifest показывается через **Настройки проекта → Показывать файл манифеста**.
3. Убедитесь, что часовой пояс проекта — `Europe/Moscow`.
4. В редакторе выберите функцию `setupDemoProject` и нажмите **Выполнить**. При первом запуске подтвердите разрешения Sheets и Drive.
5. После создания ресурсов `setupDemoProject()` выводит обе ссылки через `console.log`. Откройте журнал выполнения, чтобы перейти к таблице и папке. Возвращаемый сериализуемый объект также содержит `data.spreadsheetUrl`, `data.folderUrl` и сообщение.

`setupDemoProject()` создаёт таблицу и корневую папку **«НК-строй — демо»**, заполняет 2 прорабов, 4 объекта, 5 типов и 20 объектных позиций. Если хотя бы один ID уже записан в Script Properties, функция остановится с предупреждением и не создаст дубликат. ID ресурсов не входят в исходный код.

## Развёртывание Web App

1. Выберите **Развернуть → Новое развертывание → Веб-приложение**.
2. Первое тестирование проводите **только владельцем проекта**: укажите **Выполнять от имени: Я** и **У кого есть доступ: Только я**. Доступ `MYSELF` также задан в manifest по умолчанию.
3. Не включайте публичный доступ для первичной демонстрации. Если позднее разрешить доступ другим пользователям при выполнении Web App от имени владельца, эти пользователи смогут через приложение создавать файлы в Google Drive владельца проекта.
4. Нажмите **Развернуть**, подтвердите разрешения и скопируйте URL `/exec`.
5. Откройте URL на телефоне в браузере. Установка приложения не нужна; интерфейс адаптирован для узкого экрана.

После изменения кода создайте новую версию развертывания. Настройка `executeAs` в интерфейсе развёртывания имеет приоритет; manifest задаёт базовую конфигурацию.

## Сброс демонстрации

В редакторе выберите `resetDemoData()` и нажмите **Выполнить**. Функция восстановит исходные тестовые строки и смешанные статусы, очистит даты и ссылки.

> **Предупреждение:** `resetDemoData()` переносит в корзину все дочерние демонстрационные папки и файлы, созданные приложением внутри корневой папки. Сам Apps Script-проект, таблица и корневая папка не удаляются.

## Изменение демо-данных

- Прорабов и объекты можно менять в соответствующих листах. ID должны быть уникальны, статусы действующих записей — `Действующий`, а объект должен содержать совпадающий ID ответственного.
- Обязательные позиции для уже созданной таблицы меняются в листах **Справочник файлов** и **Файлы объектов**. Для изменения исходного seed отредактируйте `getDemoSeed_()` в `SetupService.gs`; затем выполните сброс.
- Названия/порядок заголовков можно менять только синхронно с `CONFIG.HEADERS`; перестановка существующих столбцов допустима без изменения кода.
- Ограничение отдельного файла задаётся `MAX_FILE_SIZE_MB`/`MAX_FILE_SIZE_BYTES`, а общий лимит позиции — `MAX_REQUIREMENT_TOTAL_SIZE_MB`/`MAX_REQUIREMENT_TOTAL_SIZE_BYTES` в `Config.gs`. Оба ограничения проверяются в браузере и на сервере.

## Почему ID не хранятся в GitHub

`SPREADSHEET_ID` и `ROOT_FOLDER_ID` указывают на ресурсы конкретного владельца и окружения. Публикация связывает код с инфраструктурой, облегчает нежелательное раскрытие метаданных и мешает независимым развёртываниям. Поэтому `setupDemoProject()` записывает их в **Script Properties**, откуда сервер получает значения во время выполнения.

## Технические допущения

- Клиент отправляет обязательные позиции последовательно; одна позиция обрабатывается одним серверным вызовом.
- Статус меняется только после сохранения всех файлов позиции. Полная обновлённая строка записывается одним `setValues`; при ошибке Drive или Sheets созданные в текущей попытке файлы перемещаются в корзину, ранее существовавшие не затрагиваются.
- `LockService` сериализует проверку статуса и обновление строки, предотвращая повторную загрузку одной позиции.
- Исходно предоставленные позиции визуальные: реальные файлы и ссылки для них не создаются.
- Папки с совпадающими именами повторно используются; при существовании нескольких одноимённых папок используется первая найденная.
- Архитектура отделяет выбор пользователя от серверной проверки связей, чтобы позднее заменить выбор подтверждённой идентичностью без переписывания Drive/Sheets слоя.
